# Contributing

Thanks for improving this reference sample. Fork the repository, open a focused pull request with a description and validation results, and follow the [Code of Conduct](CODE_OF_CONDUCT.md). Reviews are best-effort.

Read the README, install dependencies with `npm ci`, run `npm run check`, and verify the live response marker and headers. For changes to alternate deployment recipes, run their documented build and validation steps. Keep the example small and keep deployment recipes in sync. Use descriptive commit subjects such as `docs: clarify setup` or `fix: preserve response headers`.

For bugs use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md); for proposals use the [feature request template](.github/ISSUE_TEMPLATE/feature_request.md). Update the README when setup or behavior changes.
